# 求籤 ↔ 塔羅 導流計畫

> 狀態（2026-09-24）：**實作中**。兩個 repo 都在 `codex/stick-tarot-bridge` 分支；先完成雙 Worker 憑證兌換與頁面入口，不部署正式站。

**目標：** 利用目前由廣告導入、已有每日使用與留存的塔羅用戶，帶他們體驗求籤；讓求籤也能發展成獨立的日常習慣，並透過求籤後解鎖額外塔羅，把用戶帶回塔羅。

**每日次數規則：** 塔羅原有每天 1 次基本免費解讀。用戶完成當天第一支籤後，可解鎖 1 次額外塔羅；當日總上限為 2 次，額外次數每天最多使用一次。好友邀請額度照常累積並保留，但同一天也只能使用一份額外額度；未用的邀請額度留到之後使用。抽更多支籤不會增加額外次數。求籤不只是塔羅的導流出口，也可以成為用戶持續使用的產品。

- 求籤：https://app.manyfold.ai/fortune-stick/ （repo: manyfold-open/manyfold-fortune-stick，本機 `~/Desktop/manyfold-fortune-stick`）
- 塔羅：https://app.manyfold.ai/tarot/ （repo: manyfold-open/manyfold-tarot，本機 `~/Desktop/tarot/manyfold-tarot`；Worker 掛載在共享網域的 `/tarot/` 路徑）

**背後的規則：** 塔羅是目前的廣告入口與主要留存產品：保留每天 1 次基本免費解讀。完成當天第一支籤後，再解鎖 1 次額外塔羅（當日總上限 2 次；再抽籤不疊加）。好友邀請額度仍會累積，但任何來源的額外解讀每天最多消耗一次，未用的好友邀請額度不會被清掉。從塔羅導到求籤是讓現有用戶發現第二個產品；求籤後回塔羅是即時回報。同時，求籤也應能獨立成為每日會回來使用的產品，不把它只當作塔羅的中途站。

## 已確定的決定

- 方向：以塔羅現有流量導入求籤，並用每日一次的額外塔羅鼓勵回流；求籤也可以獨立形成日常使用。**已否決**：集冊／圖鑑、每日打卡、「應驗了嗎」回顧、推播提醒、兩站共用帳號或點數
- 所有跨 app 入口都不傳遞問題內容；① 只帶來源、語言與符合資格時的一次性獎勵憑證，開塔羅正常提問頁；②③ 開求籤首頁；④ 保留塔羅分享內容，主 CTA 開新塔羅提問頁、次要 CTA 開求籤首頁
- 求籤每日不限次數；完成當日第一支籤可解鎖 1 次額外塔羅。基本免費次數加每日一次額外次數，合計每日最多 2 次；額外次數優先用求籤獎勵，其次才用好友邀請額度。好友邀請額度會保留未用餘額，重複抽籤不會重複解鎖
- 塔羅是現有廣告獲客與留存主入口；求籤同時作為塔羅用戶的新體驗，以及可獨立培養的日常產品
- 塔羅不接收或預填求籤問題；從求籤進入時開正常提問頁，由用戶自行輸入要問的事
- ③ 條件：塔羅基本免費次數用完、今日首籤獎勵尚未領取時，才顯示「抽籤解鎖額外塔羅」；已解鎖者直接使用額外次數，不再被送回求籤領第二次
- ④ 分享連結仍然打開塔羅分享內容；主 CTA 讓朋友直接開始自己的塔羅解讀，次要 CTA 才導向求籤，不複製分享者的問題

## 第一版執行計畫

依目前示意圖，第一版只驗證這條路徑：塔羅解讀完成後邀請用戶求籤；完成當日第一支籤後，回塔羅使用一次額外解讀。塔羅分享頁保留原分享內容，讓朋友可直接開始自己的塔羅，或另選求籤。先不加塔羅首頁卡片；如果結果頁入口觸及太少，再把首頁入口列為下一個實驗。

1. **獎勵憑證按塔羅匿名 session／台灣日期限一次。** 求籤端沒有共用帳號或 session；求籤 Worker 為已完成解籤的籤簽發 HMAC 憑證，塔羅 Worker 驗簽後寫入自己的 D1。憑證只帶由籤記錄 ID 經 HMAC 推導出的不可逆編號（原始 ID 可直接查回問題，所以不能外傳）、台灣日期與到期時間，不帶問題；同一籤憑證只能用一次，每日額外次數按塔羅匿名 session 限一次。因為兩站沒有共用身分，無法阻止同一人換瀏覽器重新領取。
2. **保留好友邀請額度，同時落實每日總上限。** 額外解讀的日用量對所有來源共用一格；求籤獎勵優先，其次使用一份好友邀請額度。已累積但當日沒用到的好友邀請額度不會被清除，之後仍可使用。
3. **做兩邊主要入口。** 塔羅解讀結束後放求籤入口；求籤結果頁放回塔羅入口。求籤入口在今日獎勵尚未領取時說明首籤可解鎖一次；完成獎勵後仍可邀請用戶求籤，但不再承諾額外塔羅。
4. **整理塔羅分享頁。** 保留分享者的塔羅內容；主 CTA 讓朋友開始自己的塔羅，次要 CTA 讓朋友去求籤。兩條路都不複製分享者的問題。
5. **補足效果量測。** 塔羅已有遵循同意狀態的 GA；求籤目前沒有 GA。若要判斷求籤是否能獨立留住用戶，需決定加入不含問題、籤號或解讀內容的完成與回訪事件。至少追蹤入口點擊、完成首籤、額外塔羅兌換／使用、求籤次日回訪、塔羅次日回訪及額外解讀成本。
6. **兩個 repo 分開預覽、一起走查後再發布。** Tarot repo 目前已有未提交的每日免費一次改動；兩個 repo 合併到 `main` 都會部署正式站，因此先在 branch／preview 完成端到端走查，再安排正式發布。

### ① 求籤 → 塔羅（求籤 repo）

- 求籤結果頁保留回塔羅的入口；用戶可不限次數使用求籤，完成當日第一支籤後只解鎖一次額外塔羅
- 從求籤導到塔羅只需完成一次抽籤並在結果頁點入口，不必重複抽；進入塔羅後用戶自行輸入並提交問題，才會實際使用一次解讀
- 完成解籤後可簽發一次性兌換憑證，隨塔羅導流連結傳遞；憑證綁定籤記錄（HMAC 編號）與簽發當天的台灣日期，於該日午夜失效；午夜前一小時內抽的籤跨日完成仍算新的一天，更早的歷史籤不發憑證

- 從塔羅帶來的 `tarot_return`（須在 `TAROT_HANDOFF_URL`／`TAROT_RETURN_URLS` 白名單內）決定回跳哪個塔羅網域，舊 `tarot.manyfold.ai` 用戶回到原 session
- 後續籤仍可照常抽、照常導向塔羅，但不再發額外次數；因此求籤也能獨立留住用戶，不依賴重複發獎

- 兩個 Worker 都需要設定相同的 `TAROT_BRIDGE_SECRET`，以 `npx wrangler secret put TAROT_BRIDGE_SECRET` 分別寫入；不能把真正的值 commit

- `src/app/components/ReadingResult.tsx`：在四段解讀下面加一行文案和連結，沿用 `.text-action` 樣式（符合「動作是紙上的一行字」的設計規則）；按下時向 Stick Worker 取簽名憑證

